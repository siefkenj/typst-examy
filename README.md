# examy

A [Typst](https://typst.app) package for writing exams, quizzes, and homework
with automatically numbered questions, answer boxes, points accounting, smart
cross-references, and solutions that can be toggled on and off. This package
follows the spirit of the [exam class for LaTeX](https://ctan.org/pkg/exam?lang=en).

## Quick start

To start from a complete exam (a cover page with a points table, followed
by questions with answer boxes, parts, and multiple choice), run

```bash
typst init @preview/examy
```

or choose examy under _Start from template_ in the Typst web app. A minimal
document looks like this:

```typst
#import "@preview/examy:0.4.0": *

#show: e.prepare()
#show: e.set_(config, show-solutions: false)

// A fill-in block (Name / Student ID) at the top of the page
#name-block()

#exam(
  questions: [
    #question(points: 2)[
      State the definition of a _continuous function_.
      #answer-box(width: 100%, height: 1fr)[
        #solution[A function $f$ is continuous at $a$ if ...]
      ]
    ]
    #question(points: 3)[
      Give an example of a continuous function that is not differentiable.
      #answer-box(width: 100%, height: 2fr)[
        #solution[$f(x) = |x|$ ...]
      ]
    ]
  ],
)
```

The two `#show` lines are required: `e.prepare()` enables
[elembic](https://typst.app/universe/package/elembic) elements and references,
and `e.set_(config, ...)` sets package options.

## Features

- **[Questions, parts, and subparts](https://siefkenj.github.io/typst-examy/questions.html)**,
  numbered automatically in a style you choose, with page breaks inside them.
- **[Points](https://siefkenj.github.io/typst-examy/points.html)**: badges,
  totals, bonus points, a points table, and points per page.
- **[Answer boxes](https://siefkenj.github.io/typst-examy/answer-boxes.html)** of
  a set size, or sharing the rest of the page (`height: 1fr`).
- **[Solutions](https://siefkenj.github.io/typst-examy/solutions.html)** written
  next to their questions: one source for the exam and its answer key, with
  the key laid out exactly like the exam.
- **[Multiple choice](https://siefkenj.github.io/typst-examy/choices.html)**
  with round or square bubbles, lettered or not, filled in on the key.
- **[Cross-references](https://siefkenj.github.io/typst-examy/cross-references.html)**
  that read "(a)" or "1 (a)" depending on where they are.
- **[Cover pages](https://siefkenj.github.io/typst-examy/cover-pages.html)**: a
  title block, name fields, and institution presets.

## Development

Developed with Typst 0.15. A [dev container](.devcontainer) is provided for development.

The following commands are useful for development.

```bash
# run the test suite (asserts + a full-pipeline integration document)
./tests/run.sh
```

```bash
# build the documentation site into _site/ (open _site/index.html). Built
# with Typst's bundle and HTML export from docs/site.typ: the guide pages are
# in docs/site/pages/, and every example on them is rendered by the package
# from the code it shows. Published to GitHub Pages by
# .github/workflows/pages.yml on every push to main.
./make_site.sh
```

```bash
# regenerate the API Reference index of this README (between the
# API-DOCS-START/END markers above), from docs/readme-api.typ
./make_docs.sh
```

The API documentation has a single source: the declarations themselves.
elembic elements (`config`, `exam`, `solution`) are introspected with
`e.data(..)`, and the plain functions declare their arguments with
`e.field` through `declare_function` (src/signature.typ), the same spec
that checks every call's arguments. docs/api.typ reads both, for the
README's index and the site's reference; an export with no documentation
fails the build.

```bash
# build the publishable package in dist/examy/<version>/ — the folder to
# copy into typst/packages under packages/preview/. Runs the tests,
# compiles the examples, regenerates the README screenshots, rewrites
# example imports to @preview/examy, and validates the result via
# TYPST_PACKAGE_PATH (CI does the same and compiles a smoke-test document
# against the vendored package). Requires --tag=<TAG> or --no-tag — see
# below and `./make_dist.sh` with no arguments for why.
./make_dist.sh --tag=v0.4.0   # or: ./make_dist.sh --no-tag
```

### Making a release

1. Bump `version` in `typst.toml` — the elembic prefix, the example
   imports, and the dist layout all derive from it. Also update the
   `#import "@preview/examy:<version>"` line in `template/main.typ` (the
   `typst init` template ships verbatim, so it isn't rewritten;
   `make_dist.sh` refuses to build if it doesn't match).
2. Commit, tag, and push:
   ```bash
   git commit -am "Release v0.4.0"
   git tag v0.4.0
   git push && git push origin v0.4.0
   ```
   The tag needs to already be on GitHub before the next step, since the
   README's links are rewritten to permalinks pinned at it.
3. Run `./make_dist.sh --tag=v0.4.0` (matching the tag from step 2). If the
   tests and validation pass, it produces `dist/examy/<version>/` containing
   the package exactly as it should be published (example imports rewritten
   to `@preview/examy:<version>`, this Development section stripped from
   the README, relative links rewritten to permalinks at the tag, the
   template's `thumbnail.png` rendered from page 2 of `template/main.typ`).
4. Copy `dist/examy/<version>` into a fork of
   [typst/packages](https://github.com/typst/packages) as
   `packages/preview/examy/<version>` and open a pull request.
